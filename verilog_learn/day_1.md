# Verilog 数据类型

wire 类型表示硬件单元之间的物理连线，由其连接的器件输出端连续驱动。如果没有驱动元件连接到 wire 型变量，缺省值一般为 "Z"。

# 优先级

!（逻辑非） > ==（逻辑相等） > &（按位与） > &&（逻辑与）

在 Verilog 中，所有单目运算符（包括 !、~、一元 +/-、缩减运算符等）的优先级都处于最高层级之一。

== 属于相等运算符（Equality），而 & 属于按位运算符（Bitwise）。在 Verilog 的优先级表中，相等运算符的层级严格高于按位运算符。

按位与 & 逐位运算并返回向量，逻辑与 && 将整个操作数当作真假值并返回单比特。Verilog 的优先级表明确将按位与置于逻辑与之上。

# Moore 型与 Mealy 型输出的区分方法

| 类型 | 决定因素 | 数学公式 | 特点 |
| :--- | :--- | :--- | :--- |
| **Moore 型** | 仅由**当前状态**决定 | `Output = f(State)` | 输出与当前输入无关，输入只影响下一个状态 |
| **Mealy 型** | 由**当前状态**和**当前输入**共同决定 | `Output = f(State, Input)` | 输出随输入变化而立即变化（组合逻辑） |


# 静态时序分析 (STA) 和 动态时序模拟 (仿真) 对比

| 特性 | 静态时序分析 (STA) | 动态时序模拟 (仿真) |
| :--- | :--- | :--- |
| **是否需要测试向量** | **不需要**（穷举所有路径） | **需要**（依赖激励） |
| **验证对象** | 仅验证**时序**（Setup/Hold等） | 同时验证**功能**和**时序** |
| **运行速度** | 极快（通常在综合、布局布线后运行） | 极慢（尤其是大规模芯片的门级仿真） |
| **覆盖率** | 时序路径 100% 覆盖 | 取决于测试向量的完备性 |
| **能否发现功能Bug** | **绝对不能** | 能 |
| **能否发现异步时序问题** | 不能（通常针对同步电路） | 能发现（比如毛刺、亚稳态等） |

# assign 和 always 的核心区别
assign 用于描述“连线”式的连续赋值，而 always 用于描述“行为”式的过程赋值。assign 像在画电路图时连的线，而 always 则像是在描述这个电路模块的功能和动作

✅ 优先使用 assign 的场景
当需要描述简单的、无反馈的、纯粹的组合逻辑时，assign 是首选，代码更简洁直观。
    简单的逻辑运算：如 assign y = a & b;。
    基本的算术运算：如 assign sum = a + b;。
    信号的路由与选择：如你之前提到的用三目运算符进行多路选择。
    模块端口连接：用于连接实例化模块的输出。

✅ 优先使用 always 的场景
当需要描述时序逻辑或复杂的组合逻辑时，always 块是必需的。
    描述时序逻辑（必须用 always）
    任何需要存储状态的电路，如触发器 (Flip-Flop)、寄存器 (Register)、计数器、状态机。
    模板：使用边沿触发敏感列表（如 always @(posedge clk)）和非阻塞赋值 (<=)。

描述复杂的组合逻辑（推荐用 always @(*)）
    当逻辑包含复杂的条件分支 (if-else) 或多路分支 (case) 时，使用 always @(*) 比用嵌套三目运算符的 assign 可读性高得多。
    模板：使用电平敏感列表 always @(*) 和阻塞赋值 (=)，并确保覆盖所有分支以避免产生不期望的锁存器 (Latch)。

**关键规则与常见陷阱**
类型匹配是铁律：**assign 的左侧必须是 wire**，**always 块的赋值对象必须声明为 reg**（或 SystemVerilog 中的 logic）。这是语法层面的硬性规定，与最终综合出的硬件无关。

警惕 always @(*) 的仿真“陷阱”：always @(*) 的敏感列表由块内输入信号（右侧变量）构成。如果一个块内只有常量赋值（如 always @(*) b = 1'b0;），由于没有输入信号变化，该块在仿真时可能永远不会被触发，导致 b 保持未定义状态。而 assign 没有这个问题。

一个信号只能有一个“司机”：不要从多个 always 块或多个 assign 语句驱动同一个信号（wire 的多驱动在某些情况下如总线是允许的，但 reg 绝对不行）。这会导致“多驱动”冲突，综合或仿真结果是不确定的。

组合逻辑的完整性：在 always @(*) 块中描述组合逻辑时，确保所有可能的输入条件都有对应的输出赋值（if 要有 else，case 要有 default），否则会综合出意料之外的锁存器 (Latch)。

# T触发器
T触发器（Toggle Flip-Flop）的特性是：

当输入 T = 1 时，在时钟上升沿，输出翻转（Q <= ~Q）。

当输入 T = 0 时，在时钟上升沿，输出保持不变（Q <= Q）。

结合三目运算符，核心逻辑可以写为：Q <= T ? ~Q : Q;

# 奇偶校验的本质
统计这 数据（bus）里面到底有几个 1

偶校验 (Even Parity)：如果 bus 中 1 的个数是偶数，校验位 check 为 0；如果是奇数，check 为 1。这其实刚好等价于将所有位进行**异或运算**。

奇校验 (Odd Parity)：刚好和偶校验相反。如果 bus 中 1 的个数是奇数，校验位 check 为 0；如果是偶数，check 为 1。这等价于将所有位**异或后取反**。

Verilog 提供了一元缩减运算符：^（缩减异或）、~^ 或 ^~（缩减同或，即异或后取反）。它会对整个向量进行逐位运算并输出 1 位结果。

`^bus` 就是偶校验结果。

`~^bus` 就是奇校验结果。

# 条件运算符（三目运算符 ? :） 

它的基本语法是：
条件1 ? 结果1 : (条件2 ? 结果2 : (条件3 ? 结果3 : 结果4))

```verilog
 // 使用 assign 语句和嵌套的三目运算符
    assign mux_out = (sel == 2'b00) ? d3 : 
                     (sel == 2'b01) ? d2 : 
                     (sel == 2'b10) ? d1 : 
                                      d0; // 剩下的情况（sel == 2'b11）自然是 d0
```

# Driven（被驱动） / Not driven（未被驱动）：

在硬件描述语言中，wire 就像真实的导线。一根导线上必须要有信号来源（比如电源、地，或者前一级的输出），这就叫 Driven。

题目说 a 和 b 已经被模块外部的 input ports 驱动了（有确切的信号值）。

但是当前的 out 是一根悬空的线（currently not driven by anything）。我们的任务就是用 assign 语句，把 a & b 的逻辑结果驱动到这根名为 out 的线上。

# Multiple drivers（多驱动问题）：

题目提到："a wire cannot have more than one driver"。在真实的物理电路中，如果你把两个不同的输出直接连在同一根线上，可能会导致短路。在 Verilog 中，如果你在代码里用两个不同的 assign 语句去驱动同一个 wire，它的值就会变成未知（x）。所以，一根线只能有一个驱动源。

# Undefined value（未定义值）：

如果一根线没有任何驱动（No drivers），它的值就是未定义的（通常在高阻态 z，综合硬件时可能被当成 0，或者报错）。所以，输出端口一定要有明确的驱动逻辑。

# Vector

Vector（向量） 就是把这些相关的信号打包起来，起一个统一的名字。

语法（非常重要）：wire [7:0] w;
    这声明了一个 8-bit 的 vector，名字叫 w。
    注意：维度（dimensions）写在变量名前面，这和 C 语言数组（int w[8];）的习惯是不同的。
    [7:0] 表示最高位（MSB）是 7，最低位（LSB）是 0。

Part-select（部分选择）
    当你想从一整条总线（vector）里单独抽出一根线时，把索引（index）写在变量名后面即可，这叫 Part-select。
    同理，你也可以用 vec[2:1] 来提取向量中特定的几位（题目代码里展示了绿色箭头上的 [3]、[2] 等标记）。

拼接运算符 {}
    在 Verilog 中，大括号 {} 是拼接运算符（Concatenation）。它可以把多个小的信号，按照你写的顺序，从高位到低位拼成一个大的向量。

    比如：{a, b} 就是把 a 放在高位，b 放在低位拼起来。


# Implicit nets（隐式网络）
坑点：如果你在代码里用了一个没有声明过的变量（比如拼写错误 assign b = a; 里的 b），Verilog 会悄悄为你隐式创建一个 1-bit wire。

解决方法：题目强烈推荐在模块开头加上 `default_nettype none`，强制关闭隐式网络，这能帮你立刻发现拼写错误（编译器会直接报错，而不是悄悄生成一根 1-bit 的线）。

# Packed vs. Unpacked Arrays（打包数组与非打包数组）：

Packed（打包）：写在变量名前面，如 reg [7:0] mem;，这些位在硬件中紧密排列。
Unpacked（非打包）：写在变量名后面，如 reg mem [255:0];，通常用于存储器数组（Memory）。

# 按位运算符（Bitwise） 与 逻辑运算符（Logical）
Bitwise Operators（按位操作符，如 |, &, ^, ~）：
    对两个 N-bit 的 vector 进行操作时，是逐位（bit-by-bit）进行的。
    结果：产生一个 N-bit 的输出。
    例子：3'b101 | 3'b010 -> 逐位相或 -> 结果 3'b111。

Logical Operators（逻辑操作符，如 ||, &&, !）：
    把整个 vector 当成一个布尔值（Boolean value）来看待。
    规则：非零即为真（true），零即为假（false）。
    结果：永远只产生一个 1-bit 的输出（1 或 0）。
    例子：3'b101 || 3'b010 -> 两边都非零（都是真）-> 结果 1'b1。
    
# 仿真器中的多位宽（multi-bit）的向量

在仿真波形图（Simulation Waveform）中，对于多位宽（multi-bit）的向量，仿真器默认使用的是 **十六进制**（Hexadecimal，简写为 Hex） 来显示，而不是二进制（Binary）。

# Reduction Operators（归约运算符）
在 Verilog 中，如果你把按位运算符（&, |, ^）放在一个向量的最前面，且只有一个操作数，它就会自动进行“归约”操作。

`&in` 等价于 `in[3] & in[2] & in[1] & in[0]`

`|in` 等价于 `in[3] | in[2] | in[1] | in[0]`

`^in` 等价于 `in[3] ^ in[2] ^ in[1] ^ in[0]`

# 拼接的规则
拼接的规则：必须指定位宽！
    {1, 2, 3} 是非法的，在拼接时，Verilog 需要明确知道每个部分的准确位宽，才能算出总宽度。必须写成 {1'b1, 2'b10, 3'b011} 这种明确位宽的形式。
左侧拼接
    `assign {out[7:0], out[15:8]} = in;`把 in 的 16 位，低 8 位赋给 out[7:0]，高 8 位赋给 out[15:8]。这就实现了“字节交换”。
    ```
    左边的虚拟向量： [15 ........................ 8 | 7 .......................... 0]
                       (高8位)                              (低8位)
                         ↓                                     ↓
    左边拼好的实际线：  out[7:0]                            out[15:8]
                        ↑                                       ↑
    右边输入的位：      in[15:8]                             in[7:0]
                    (in的高8位)                             (in的低8位)
    ```
截断与零扩展（Truncation & Zero-extension）
    `assign out[15:0] = {in[7:0], in[15:8]}; `（左边 16 位，右边 16 位。out 的高 8 位 [23:16] 未赋值）。
    `assign out = {in[7:0], in[15:8]};`（左边是 24 位，右边是 16 位）。此时，右侧会自动零扩展（补零）至 24 位。out 的高 8 位会被自动赋值为 0。

```verilog
module top_module (
    input wire [4:0] a, b, c, d, e, f,
    output wire [7:0] w, x, y, z );

    // 利用左侧拼接，直接将右侧拼接的结果赋值给输出
    assign {w, x, y, z} = {a, b, c, d, e, f, 2'b11};
    //编译器会自动根据左边每个变量的位宽（w 是 8 bit，x 是 8 bit...），把右边长长的 32-bit 数据从高位到低位依次填入。
endmodule
```

# 实例化
>你不能直接把它的代码复制粘贴过来，而是要实例化（Instantiate）它。这就像照着图纸造一个真实的元器件，然后把它焊接到你的大电路板上。

**By name（按名称连接）：**

语法：mod_a 实例名 (.子模块端口名(外部信号名), ...);

逻辑：以 . 开头，明确指出要把外部的哪根线连到内部的哪个端口。

优点：顺序完全无所谓。只要名字对上了，怎么排都不会错。这是工业界 99% 场景下使用的标准写法。
```verilog
module top_module ( 
    input a, 
    input b, 
    output out );

    // 实例化 mod_a，实例名随意起（比如 inst1）
    // 将外部的 a 连到 in1，b 连到 in2，out 连到 out
    mod_a inst1 (
        .in1(a),
        .in2(b),
        .out(out)
    );

endmodule
```
**By position（按位置连接）：**

语法：mod_a 实例名 (外部信号1, 外部信号2, ...);

逻辑：完全按照子模块声明时 input in1, input in2, output out 的顺序，依次填入你的线 a, b, out。

缺点：这就像 C 语言里的函数传参。如果以后 mod_a 的设计者把端口顺序改了，你的代码全都会连错，而且很难排查。
```verilog
module top_module ( 
    input a, 
    input b, 
    output out );

    // 必须严格按照 mod_a 声明时的顺序：in1, in2, out
    mod_a inst1 (a, b, out);

endmodule
```

# always @(*) 是什么意思？ 

这代表组合逻辑。* 是通配符，意思是只要 always 块内部用到的任何一个输入信号（如 sel, d, q1...）发生变化，这个代码块就会被重新执行。

# case语句
```verilog
// 4 选 1 多路选择器
    always @(*) begin
        case (sel)
            2'b00: q_mux = d;
            2'b01: q_mux = q1;
            2'b10: q_mux = q2;
            2'b11: q_mux = q3;
        endcase
    end
```

# input、output、inout类型
input：默认是 wire 类型，且通常只能是 net 类型，不能声明成 reg。

output：默认也是 wire 类型，但可以显式声明为 reg，用于过程赋值。

inout：默认是 wire，一般也只能是 net 类型。
